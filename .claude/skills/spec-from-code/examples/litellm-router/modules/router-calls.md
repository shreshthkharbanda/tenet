# Per-call execution, streaming recovery and non-chat endpoint wrappers (RCALL)

## Purpose
This module is the part of the `Router` class that executes one routed attempt. It takes the deployment
that selection picked, binds it into the call's keyword arguments (metadata, tags, credentials, client,
timeouts, tools), calls the provider SDK function, and counts the outcome. For streaming results it wraps
the stream so that a failure after the stream opened can still be retried within the model group, sent
to the fallback chain, or (for chat completions, when enabled) continued on another deployment by
assistant prefill. It also holds the thin public wrappers for non-chat endpoints (image generation,
transcription, speech, rerank, text completion, adapters, guardrails, search, generic API calls), the
batch helpers, and the priority-scheduler entry. Retry and fallback loops themselves, deployment
selection and cooldowns are decided elsewhere; this module decides what one attempt sends, what it
records, and how a broken stream is recovered.

Terms used below:
- *Model group*: the public `model_name` a caller asks for; many deployments can share it.
- *Deployment*: one configured `litellm_params` block (provider model, credentials, limits) with a
  `model_info.id`.
- *Metadata bucket*: the request dict under `metadata` or `litellm_metadata` that the router writes
  bookkeeping into, in place.
- *Mid-stream error*: a `MidStreamFallbackError` raised by the SDK stream wrapper when a stream fails
  after it opened. It carries `generated_content` (text already produced), `is_pre_first_chunk`,
  `emitted_disqualifying_content` and `original_exception` (the provider error).
- *Committed stream*: a stream whose generated output already reached the caller, so a restart would
  duplicate or overlap output.
- *Fallback chain*: the router's cross-group fallback dispatcher (`async_function_with_fallbacks_common_utils`
  in router-dispatch), re-entered here with the same request kwargs.

## Implementation notes
Informative.
- The async chat wrapper keeps only a weak reference to itself inside its generator ([RCALL-016]) so that interpreter refcount teardown frees a dropped wrapper promptly; for a stream already iterated this is why slot release does not depend on garbage collection cycles, but a generator that never started has no `finally` to run, so an un-started wrapper releases nothing ([RCALL-200]).
- Reading the first chunk inside the attempt ([RCALL-053]) is what makes "dies before the first chunk" a normal pre-stream failure: the wire tests show the same retry count and `x-litellm-attempted-fallbacks` value as a non-streaming request with the same chain.
- The Responses and Anthropic wrappers subclass or mimic SDK stream types only so that downstream `isinstance` checks and header readers keep working; they bypass the base constructors.
- Several private names (`_acompletion`, `_update_kwargs_with_deployment`, the stream iterators, the generic helpers) are named in this spec because other router modules and the endpoint factory call them by name; they are the contract between modules of the same class.

- [RCALL-190] {confirmed} `litellm/router.py:5527-5546` `arerank` writes the language's built-in `input` function into the request kwargs under `input`, overwriting any value the caller passed, and that object is forwarded to the provider call ([RCALL-104], [IF-317]). Looks unintended because the value is a built-in function rather than anything the caller supplied. Impact: every routed rerank call carries a non-serialisable callable, and a caller's own `input` is lost; how providers react is open ([RCALL-182], [IF-318]).

Impact: a Responses client can receive events from two different responses in one stream.
- [RCALL-192] {confirmed} `litellm/router.py:3492-3494` When the fallback for a broken chat stream returns a non-streaming result, the stream yields a single `None` chunk and ends ([RCALL-011]). Looks unintended because the fallback's content is discarded and `None` is not a stream chunk ([RCALL-185]). Impact: the client receives a truncated stream, or a consumer error on `None`, instead of the fallback's answer.
- [RCALL-194] {confirmed} `litellm/router.py:5234-5286` Sync `image_generation` counts `total_calls`, `success_calls` and `fail_calls` under the empty-string key instead of a model name ([RCALL-106]).
