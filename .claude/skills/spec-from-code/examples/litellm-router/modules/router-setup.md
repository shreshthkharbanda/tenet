# Router construction, configuration and completion entry points (RSETUP)

## Purpose
This module is the first 3,315 lines of `litellm/router.py`. It decides how a `litellm.Router` is built from its keyword settings: which caches and Redis backend it uses, which retry, fallback, timeout and cooldown defaults apply, which strategy selector serves each model (top-level `routing_strategy`, named `routing_groups`, or a per-request override), which optional pre-call-check callbacks are registered on the process-global callback lists, and which endpoint attributes (`aresponses`, `aanthropic_messages`, vector-store, video, container and other calls) exist on the instance. It also owns the chat-completion entry points `completion` and `acompletion`, which stamp request bookkeeping and hand the call to the retry and fallback loop, plus the per-attempt sync body `_completion`, the silent-experiment (shadow traffic) launcher, and a set of module-level helpers and stream wrapper classes that the streaming and fallback code in later ranges of the same file relies on.

## Validation rules
Construction checks run in source order; the first failing check raises out of the constructor:
1. Redis client construction, including JSON parsing of `REDIS_CLUSTER_NODES` ([RSETUP-010], [RSETUP-011]).
2. Deployment loading and environment gating through `set_model_list` ([RSETUP-022], [RSETUP-203]-[RSETUP-206]).

## Implementation notes
Informative.
- The class is one very large type; this range holds its constructor and configuration surface, and the selection, dispatch and deployment ranges read the attributes set here (`cache`, `cooldown_cache`, `health_state_cache`, `num_retries`, `max_fallbacks`, `timeout`, `fallbacks`, `retry_policy`, `routing_groups`, selector attributes, `optional_callbacks`).
- Strategy selectors are stored twice for back-compat: the default group's selector in a legacy `*_logger` attribute ([RSETUP-069]), and group selectors in a per-group map ([RSETUP-091]). `get_settings` and external callers read the legacy attributes.
- Selectors double as logging callbacks: least-busy counts in-flight requests from the pre-call (input) callback list and releases them from success/failure callbacks, which is why it alone is registered on `litellm.input_callback` ([RSETUP-078]). Override selectors are bound per request instead of globally ([RSETUP-104]) so that a key- or team-level override does not make every request report to them.
- Endpoint attributes are built at construction because the wrapper needs the bound router; that is why they never appear as `def`s, and why the container-file attributes come from a JSON-generated table ([RSETUP-122]).
- The module-level helpers and the two wrapper classes at the top of the file exist for the streaming iterators in router-calls ([RCALL-003], [RCALL-029], [RCALL-140]); they are specified here because they are implemented in this range. The two small frozen dataclasses for stream-retry outcomes (`router.py:875-887`) are plain records with no behavior.
- `_stream_fallback_error_for_raised` reuses `litellm.should_retry`, whose status list (`408`, `409`, `429`, `>= 500`) is load-bearing for stream retries ([RSETUP-227]); the Anthropic-only status rule ([RSETUP-230]) excludes `408` and `409`.
- `openai.DEFAULT_MAX_RETRIES` leaks through as the router's default retry count ([RSETUP-031]); a different openai version could change it.

## Suspected defects
Behavior that looks unintended. The normative sections above state what the code does; each claim here says why it looks wrong and who is affected.

- [RSETUP-297] {confirmed} `litellm/router.py:3173-3188`, `litellm/router.py:5044-5059` Setting `default_priority` to any int makes every `acompletion` call raise `TypeError` ([RSETUP-284]). Looks unintended because `default_priority` exists only to give unprioritised calls a queue priority ([RSETUP-191]), yet `schedule_acompletion` never receives it and re-enters `acompletion` without `priority` ([RCALL-091]), so the setting cannot work, and no test sets it. Impact: an SDK user or proxy that configures `default_priority` loses every async chat call, including calls that send no `priority`.
- [RSETUP-298] {confirmed} `litellm/router.py:1630-1651`, `litellm/router.py:1756-1764`, `litellm/router.py:1625-1628` `discard()` leaves the router's strategy selectors, its Slack alerting logger and the continuation-prefill check on the process-global callback lists ([RSETUP-064], [RSETUP-061]). Looks unintended because `discard()` exists to detach a router from the process (it removes every bound-method callback, [RSETUP-062]) and the open question [RSETUP-286] records no reason for the exception. Impact: the proxy builds and discards a throw-away Router per `user_config` request, so in a long-running proxy the callback lists grow with every such request and every later logging event visits the stale selectors.
- [RSETUP-299] {confirmed} `litellm/router.py:1473-1478`, `litellm/router.py:1490-1497`, `litellm/router.py:1551-1557` Construction mutates caller-owned inputs in place: the `{"*": ...}` default-fallback entry is appended to the caller's `fallbacks` list or to the process-global `litellm.fallbacks` ([RSETUP-038]), `"router_budget_limiting"` is appended to the caller's `optional_pre_call_checks` list ([RSETUP-051]), and the caller's `default_litellm_params` dict gains `timeout`, `max_retries` and `metadata.caching_groups` ([RSETUP-043]). Looks unintended because none of these side effects is documented and the global-list case repeats on every construction ([RSETUP-289]). Impact: building several routers from one settings object, or from the `litellm.*` globals, accumulates duplicate wildcard fallback entries and carries one router's defaults into the next.
- [RSETUP-300] {inferred} `litellm/router.py:1490-1491`, `litellm/main.py:396-435` `router.chat.completions.create(...)` writes each call's kwargs into the router's shared `default_litellm_params` dict ([RSETUP-042], [IF-444]). Looks unintended because a per-call argument then becomes a default that the router merges into every later call ([RCALL-064]). Impact: an OpenAI-style client that passes, for example, `temperature` or `user` once applies it silently to all later requests on that router (inferred: the write happens in `litellm.Chat`, outside this module).
- [RSETUP-301] {confirmed} `litellm/router.py:1529-1601` A constructor that raises after its callbacks are registered leaves the half-built router's callbacks, selectors and pre-call checks on the process-global lists ([RSETUP-264]). Looks unintended because the half-built object is unreachable after the exception, so nothing can `discard()` it. - [RSETUP-307] {confirmed} `litellm/router.py:8575`, `litellm/router.py:9387-9410`, `litellm/router.py:3001-3008` The content-policy rule ignores a request-level `content_policy_fallbacks` ([RSETUP-303]).
